01 / What is Cloud?

Someone else's
computer —
on demand.

Cloud computing means accessing computing resources — servers, storage, databases, networking — over the internet, instead of owning and running physical hardware yourself. You pay only for what you use.

💡

Analogy: Electricity from the grid vs building your own power plant. You don't need to own or manage the infrastructure — you just plug in and pay per unit used. Cloud = the electrical grid for computing.

💡 The three big benefits

Elasticity: Scale up in seconds, scale down when done.
Global reach: Deploy in 30+ regions worldwide instantly.
Pay-as-you-go: No upfront cost — pay only for what you consume.

02 / Service Models

How much do you
want to manage?

Cloud services come in three layers. Each layer removes more responsibility from you — but also gives you less control. Pick the layer that matches what you actually need to manage.

🍕

Analogy — Pizza:
IaaS = buy ingredients from the store, cook yourself
PaaS = use a restaurant kitchen and appliances, cook yourself
SaaS = just order delivery, eat the result

💡 Rule of thumb

IaaS if you need full control (e.g., custom OS, specialised software).
PaaS for developer productivity (just deploy code, no infra management).
SaaS when you just need the end product (Gmail, Salesforce).

03 / Core Building Blocks

Every cloud app uses
these four primitives

No matter which cloud provider, the same fundamental services appear everywhere. Master these and you can work with any cloud.

🖥️

Compute

Virtual machines (EC2, Azure VMs) or serverless functions (Lambda, Cloud Functions). Run your code without buying hardware.

EC2 instance: $0.023/hr
Lambda: $0.0000002/request
Scale 0 → 10,000 in 60s
🗄️

Storage

Object storage (S3, Blob) for files. Block storage (EBS, Disk) for VMs. Database services (RDS, DynamoDB) for structured data.

S3: $0.023/GB/month
11 nines (99.999999999%)
durability — almost unfailable
🌐

Networking

Virtual Private Cloud (VPC) isolates your resources. Load Balancers distribute traffic. CDNs deliver content from the nearest edge location.

VPC: your private network
Subnets: segments within VPC
Security Groups: firewall rules
🔐

Identity (IAM)

Identity & Access Management controls WHO can do WHAT on your cloud. Every action requires a permission. Principle of least privilege.

Role: DevTeam
Allow: s3:PutObject
Deny: ec2:TerminateInstances
04 / Scaling

Grow up or
grow out —
automatically.

When traffic spikes, cloud apps can scale automatically — either by making one server bigger (vertical) or by adding more servers (horizontal). Auto-scaling groups watch your metrics and react in seconds.

🚗

Analogy:
Vertical scaling = replace your car with a bigger truck
Horizontal scaling = add more cars to your fleet
Horizontal is preferred — no single point of failure, virtually unlimited scale.

💡 Auto-scaling in action

A load balancer sits in front of your fleet. When CPU > 70%, it spins up a new server and registers it. When traffic drops, it terminates extra instances. You only pay for what's running.

05 / Cloud Providers

Three giants.
Which one to choose?

AWS, Azure, and GCP all offer the same fundamental services. Your choice often depends on existing tech stack, team experience, or specific services you need.

🟠

AWS

Largest market share (~33%). First mover, most services (200+), deepest ecosystem. Steeper learning curve.

S3 · EC2 · Lambda · RDS Best for: startups, broad use
🔵

Microsoft Azure

Strong enterprise play (~22%). Best integration with Windows, Office 365, Active Directory. Preferred by large companies.

Blob · VMs · Functions · SQL Best for: enterprise, Microsoft shops
🟢

Google Cloud (GCP)

Strongest on data & ML (~11%). BigQuery, Vertex AI, Kubernetes (GCP invented K8s). Preferred by data-heavy workloads.

GCS · GKE · BigQuery · Vertex Best for: ML/data, Kubernetes
