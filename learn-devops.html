01 / What is DevOps?

Dev + Ops
working as
one team.

DevOps is a culture and set of practices that bring development (building features) and operations (running infrastructure) together. The goal: ship software faster, more reliably, and with fewer incidents.

🏗️

Analogy: Old model = architects hand blueprints to builders, who hand buildings to facilities managers — each blames the other when something breaks. DevOps = one cross-functional team owns the whole lifecycle: design → build → deploy → monitor → improve.

💡 The three pillars

Automation: Everything that can be scripted, should be. No manual deploys.
Feedback loops: Errors surface in minutes, not months.
Collaboration: Shared responsibility for reliability (no blame silos).

02 / CI/CD Pipeline

Code to
production in
minutes.

CI (Continuous Integration) means every code commit is automatically tested. CD (Continuous Delivery/Deployment) means passing code is automatically deployed. Together they eliminate manual, risky "big bang" releases.

🏭

Analogy: A car factory assembly line. Each station (test, build, scan, deploy) does one job and passes the car forward. If any station finds a defect, the line stops and the developer is alerted immediately — not after the car is shipped to a customer.

1
Code Commit

Developer pushes to Git. This triggers the pipeline automatically.

2
Build

Source code is compiled and dependencies installed.

3
Test

Unit, integration, and e2e tests run in parallel.

4
Security Scan

Static analysis, dependency audit, container scan.

5
Deploy

Artifact pushed to staging, then production (blue/green or canary).

03 / Docker & Containers

"Works on
my machine"
— solved.

A container packages your app with all its dependencies (libraries, runtime, config) into a single portable unit. It runs identically on your laptop, CI server, or production — because the environment travels with the app.

📦

Analogy — Shipping container: Before containers, ports were chaos — every cargo needed different handling. The standard shipping container changed everything: load it once, ship anywhere. Docker containers do the same for software.

💡 VM vs Container

VMs: Virtualise entire hardware, each runs its own full OS (gigabytes, minutes to start)
Containers: Share the host OS kernel, isolate just the app process (megabytes, milliseconds to start)
→ Containers are 10–100x more resource-efficient.

04 / Kubernetes

Orchestrate
thousands of
containers.

Kubernetes (K8s) is a system that automates deployment, scaling, and management of containerised applications. It watches your containers, restarts failed ones, scales based on load, and distributes traffic — automatically.

🎼

Analogy — Orchestra conductor: Docker packages musicians (containers). Kubernetes is the conductor — assigns seats, fills in for anyone who leaves, scales the string section when needed, keeps everything in sync, without you micromanaging every musician.

💡 Core K8s concepts

Pod: Smallest unit — one or more containers running together.
Deployment: Declares how many pod replicas you want; K8s maintains that count.
Service: Stable network endpoint in front of pods (pods come and go, service IP stays).
Node: Physical/virtual machine that runs pods.

05 / Infrastructure as Code

Your infrastructure
in a Git repository.

IaC means you describe servers, networks, and databases in config files — not by clicking in a web console. Same code, same infrastructure, every time. Reviewed, versioned, reproducible.

🌍

Terraform

Cloud-agnostic. Write once, deploy to AWS, Azure, GCP, or any provider. Most popular IaC tool. Uses HCL language.

resource "aws_instance" "web" { ami = "ami-0c55b31ad" instance_type = "t3.micro" }
📜

Ansible

Configuration management. Once your server exists, Ansible installs packages, configs, and software — idempotently (same result if run 10 times).

- name: Install nginx apt: name: nginx state: present
🔥

Pulumi / CDK

Write infrastructure in real programming languages (Python, TypeScript, Go). Loops, functions, and tests work natively. Best for complex, dynamic infra.

const server = new aws.ec2 .Instance("web", { instanceType: "t3.micro" });
